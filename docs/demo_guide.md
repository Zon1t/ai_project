# RedFix 시연 진행 가이드

> 발표자용. 시연 시간 약 12~15분 기준. 화면 조작은 모두 브라우저(http://localhost:8501)에서 합니다.

---

## 1. 전날 준비 (30분)

| 확인 | 명령·방법 | 정상 상태 |
|---|---|---|
| 가상환경·의존성 | `.venv\Scripts\Activate.ps1` | 오류 없음 |
| API 키 | 프로젝트 루트 `.env`의 `OPENAI_API_KEY` | 실시간 모드에서 실행 가능 |
| 검색 색인 | `$env:PYTHONPATH="src"; python -m sr_agent.rag.index` | `data/chroma/` 생성 (처음 한 번, 임베딩 모델 약 2GB 다운로드) |
| 테스트 | `pytest tests` | 모두 통과 |
| 화면 | `streamlit run app/streamlit_app.py` | 재생 모드에 SR-2041·2077·2103이 보임 |
| 실시간 리허설 | 실시간 모드 → SR-2103 → **실행** | 3~4분 안에 "승인 대기" |

리허설로 실행한 실시간 결과는 `runs/`에 남습니다. 시연 당일 실시간으로 다시 보여 주려면 **처음부터 다시**를 켜고 실행합니다.

**재생 데이터를 새로 녹화하려면** (실시간 결과가 더 좋게 나왔을 때):

```powershell
$env:PYTHONPATH = "src"
python -m sr_agent.run --ticket SR-2103 --restart
python -m sr_agent.ui save-replay SR-2103
```

## 2. 시연 순서

재생 모드로 흐름을 먼저 보여 주고, 마지막에 실시간 실행으로 "진짜로 돈다"는 것을 보여 줍니다.
실시간 실행은 3~4분 걸리므로 **시연 시작 직후 다른 브라우저 탭에서 먼저 눌러 두는 것**을 권합니다.

### 0단계 · 시작 전 (30초)

1. 브라우저 탭 두 개를 엽니다.
2. **탭 B**: 사이드바 모드 **실시간** → **SR-2103** → **처음부터 다시** 켜기 → **실행**. 그대로 둡니다.
3. **탭 A**: 모드 **재생**. 여기서 발표를 진행합니다.

### 1단계 · 문제 소개 (1분)

- "운영 SR 한 건에 원인 찾기·회귀 확인·근거 대조로 1~2시간이 듭니다."
- 오른쪽 위 **사용 설명서**를 잠깐 열어 단계 표(분석 → 수정 → 공격 → 판정 → 승인)를 보여 주고 닫습니다.
- 강조점: **통과 여부는 LLM이 아니라 코드가 판정**하고, 반영은 사람이 승인합니다.

### 2단계 · S1 결함 수정 — SR-2041 (4분)

1. 사이드바에서 **SR-2041** 선택 → **진행 과정 재생**.
   - 진행 막대 한 줄과 단계 배지가 바뀌는 것을 보여 줍니다 (약 10초).
2. 끝나면 펼쳐지는 **처리 과정** 표: "분석 3분, 공격 2분… 전체 5분 45초"를 짚습니다. KPI 목표 15분 이내.
3. **결론 카드**: 판정 조건 6/6, 기존 테스트 1,145개 통과.
4. **결함 위치** 탭이 핵심 장면입니다.
   - 모델 1위는 증상이 드러나는 함수, 에이전트는 원인 함수 `discount.apply_coupon`(모델 2위)를 골랐습니다.
   - **모델 1위를 고르지 않은 이유**를 펼쳐 읽어 줍니다. "예측은 참고 자료, 최종 판단은 근거로."
5. **근거** 탭: `BIZ-CPN-01`·`BIZ-CPN-02` 규칙 → "사내 규칙을 인용해서 고쳤다."
6. **공격 로그** 탭: 공격이 "미달"이라고 주장한 입력을, 판정이 정답과 같다고 확인해 통과시킨 장면.
   - "LLM은 입력만 제안하고, 맞고 틀림은 코드가 다시 실행해서 정합니다."

### 3단계 · S2 코드 표준화 — SR-2077 (3분)

이 시나리오는 **공격이 문제를 찾아 재시도하는 흐름**이 실제로 나온 사례입니다.

1. **SR-2077** 선택 → 재생.
2. 처리 과정 표: 수정 1 → 공격 1 → **판정 1 실패** → 수정 2 → 공격 2(라운드 5회) → 판정 2 통과.
3. **공격 로그** 탭 → 시도 선택에서 **시도 1 실패**: 시간대가 붙은 입력에서 원본과 결과가 달라진 회귀 2건.
4. **시도 2 통과**로 바꾸고 **패치 diff** 탭에서 `datetime.utcnow`·`pytz` → `datetime.now(timezone.utc)`·`zoneinfo` 교체를 보여 줍니다.

### 4단계 · S3 보안 조치 — SR-2103 (2분)

1. **SR-2103** 선택 → 재생 (짧게).
2. **패치 diff**: f-string SQL → `?` 파라미터 바인딩. **근거** 탭의 `SEC-SQL-01`.
3. 판정 조건 상세: "공격 입력 무력화" — 인젝션 입력 4종을 막았는지 코드로 확인.

### 5단계 · 실시간 실행 확인 (2분)

1. **탭 B**로 이동합니다. 끝났으면 "승인 대기" 상태와 처리 과정 요약이 보입니다.
   - 아직 진행 중이면 진행 막대의 현재 단계를 보여 주고, 끝날 때까지 질문을 받습니다.
2. **판정 조건 상세** → **승인 후 반영** → "승인됨 · 결과물 approved.diff".
   - "판정을 통과한 것만 승인 버튼이 켜집니다. 실제 반영은 이 diff로 사람이 합니다."

### 6단계 · 성과 정리 (2분)

`eval/results/kpi_ablation.md`의 표를 보여 줍니다.
- E2E 해결률, 예측 도구·공격 단계 유무별(Ablation) 비교, 회귀 누출 수.
- 한계도 함께 말합니다: 새로 등록한 티켓은 정답 구현이 없어 일부 조건이 "미평가"로 표시되고, 그때는 사람이 직접 확인합니다(사용 설명서 6장).

## 3. 문제가 생겼을 때

| 상황 | 대응 |
|---|---|
| 실시간 실행이 오래 걸림 / API 오류 | 탭 B는 두고 재생 모드로 계속 진행. 마지막에 "리허설 결과"로 `runs/`에 남은 상태를 보여 줌 |
| 실시간 결과가 "사람 검토" | 오히려 장면으로 씁니다: 위쪽 경고의 사유와 판정 조건을 보여 주고 "통과 못 하면 사람에게 넘긴다"를 설명 |
| 재생 중 승인을 눌러 버림 | **승인·반려 기록 초기화** |
| 화면이 안 뜸 | 터미널에서 `streamlit run app/streamlit_app.py` 다시 실행 |

## 4. 예상 질문

| 질문 | 답 |
|---|---|
| LLM이 틀리게 고치면? | 판정이 코드로 검사(재현 테스트, 기존 테스트 1,145개, 변경 범위, 정답 구현과 입력 200개 비교)하고, 실패하면 최대 3번 다시 고친 뒤 사람에게 넘깁니다 |
| 처음 보는 결함도 찾나? | 예측 모델은 결함 패턴이 아니라 티켓-코드 유사도·스택트레이스·함수 특성으로 점수를 매겨 새 결함·새 함수에도 씁니다. 최종 위치는 에이전트가 코드로 확인합니다 |
| 실제 회사 코드에 쓰려면? | 대상 프로젝트, 사내 규칙, 과거 이력 데이터를 그 회사 것으로 바꾸고 모델을 다시 학습합니다. 이 프로젝트는 가상 데이터만 씁니다 |
| 비용은? | 티켓당 약 $0.4~1, 토큰 상한 150만 |
