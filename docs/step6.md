## 2. 실패 원인별 보완

5일차 Ablation에서 해결하지 못하거나 누출된 티켓을 원인별로 나눴다.

| 티켓 (조건) | 원인 | 보완 | 기대 효과 |
|---|---|---|---|
| `review.can_write_review` (전체, 3회째 통과 후 누출) | 1회째 공격 입력을 3회째 판정이 다시 실행하지 않음 | 판정이 이전 시도 공격 입력까지 누적 재실행 (`graph.judge_attack_inputs`) | 같은 입력으로 되돌아간 패치는 판정 실패 |
| `tax.split_mixed_items` (전체·예측 끔, 누출) | 숨긴 테스트의 입력을 판정이 보지 못함 (같은 원인 가능성) | 위와 같음. 재측정으로 확인 필요 | 확인 필요 |
| `shipping.decide_return_fee_payer` (3조건 모두 분석 실패) | `read_method`가 함수만 보여 줘 분기 기준 상수(`SELLER_FAULT_REASONS`)를 모름 → 재현 테스트에 `"상품 불량"` 같은 지어낸 사유 코드 | `read_method`가 참조 모듈 상수를 함께 반환, 분석 프롬프트에 "입력값을 지어내지 않는다" 추가 | 코드에 있는 `"DEFECT"` 등을 사용 |
| `settlement.settle_order` (전체, 분석 실패) | 재현 테스트가 결함 동작(`> expected`)을 단언 | 프롬프트에 이미 "올바른 동작을 기대" 규칙 있음. 이번에는 미반영 | 재측정 후 판단 |
| `test_e2e.py` 2건 (이 PC) | clone 시 `autocrlf=true`로 대상 코드가 CRLF → 결함 데이터 해시 불일치, OneDrive 읽기 전용 폴더 | 저장소 `core.autocrlf=false`, 줄바꿈 LF 복원, `remove_tree` | 통과 |

## 3. 새 결함·새 코드에 대한 동작 (질문 정리)

- **결함 위치 예측**은 결함 패턴을 외운 모델이 아니다. 피처가 티켓-코드 유사도(TF-IDF·bge-m3), 스택트레이스 일치, 함수 길이·복잡도라, 학습에 없던 결함과 새로 추가된 함수에도 점수를 매긴다. "과거 결함 수"는 주 모델에서 이미 뺐다 (처음 보는 함수에서 Top-3 0.775 → 0.295로 무너짐).
- 예측은 참고 자료이고, 분석 에이전트(LLM)가 코드·호출 관계·이력·재현 테스트로 최종 위치를 정한다. 홀드아웃 20건에서 모델 Top-3 85%, 에이전트 최종 위치 100%.
- **한계**: 화면에서 새로 등록한 티켓은 정답 구현이 없어, 판정의 "정답 구현과 동일(Hypothesis)"·"공격 입력 재판정"이 미평가다. 이때 통과 여부는 재현 테스트·기존 테스트·변경 범위로만 정해지므로, 화면이 미평가 조건을 알리고 승인 전 직접 확인하게 했다. 사용 설명서 6장.
- **다른 프로젝트**에 쓰려면 `target/` 교체 후 사내 규칙·이력 색인을 다시 만들고 모델 재학습을 권장한다.
